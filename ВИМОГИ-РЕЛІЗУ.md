# Вимоги до релізної станції VRX-GL

Що мусить бути на станції (Orange Pi 5 Plus, RK3588), щоб працювало все:
показ, запис, звук, плеєр, редактор розкладки, оновлення з флешки, час для
камери. Документ — і вимоги, і порядок встановлення: після підключення
станції по SSH усе ставиться з машини розробки за цим списком, а розділ
«Перевірка» каже, як переконатись, що вийшло.

Позначки: **[є]** — уже стоїть у `vrx-deps/setup.sh`; **[НОВЕ]** — додалось
відтоді, у старих образах цього немає.

---

## 1. Залізо й ОС

| | |
|---|---|
| Плата | Orange Pi 5 Plus, RK3588 |
| ОС | Debian 12 Bookworm **Server/CLI**, arm64 |
| Ядро | `6.1.99-rockchip-rk3588` (вендорське — від нього залежать Mali й MPP) |
| Носій системи | microSD (до неї прив'язана ліцензія станції — див. §11) |
| RTC | з батарейкою: у полі інтернету немає, і час станції — єдине джерело часу для камери (§5) |

Графічної сесії (lightdm, gdm, робочого стола) **бути не повинно**: станція
бере DRM master сама, і дисплейний менеджер не дав би їй піднятись.

---

## 2. Пакети з Debian (apt)

Лише рантайм, без `-dev`: на станції нічого не збирається, бінарники
приходять зібраними.

| Пакет | Навіщо | |
|---|---|---|
| `gstreamer1.0-plugins-base` | appsink, opusdec, opusparse, audioconvert, volume, videoconvert | [є] |
| `gstreamer1.0-plugins-good` | udpsrc, rtph265depay, rtpopusdepay, matroskamux/demux, jpegenc, level | [є] |
| `gstreamer1.0-plugins-bad` | h265parse, jpegparse | [є] |
| `gstreamer1.0-tools` | gst-inspect для перевірок | [є] |
| **`gstreamer1.0-alsa`** | **alsasink — без нього звуку немає взагалі** | **[НОВЕ]** |
| `libsdl2-2.0-0`, `libsdl2-image-2.0-0`, `libsdl2-ttf-2.0-0` | редактор розкладки (тягне й libasound2) | [є] |
| `fonts-dejavu-core` | шрифт інтерфейсу редактора | [є] |
| `libx11-6`, `libx11-xcb1`, `libxcb-dri2-0` | Mali збірки x11-gbm | [є] |
| `libssl3`, `libdrm2`, `liborc-0.4-0`, `libunwind8`, `libdw1` | залежності станції | [є] |
| `xserver-xorg-core`, `xinit`, `xserver-xorg-input-libinput`, `libgl1-mesa-dri` | лише для редактора розкладки | [є] |
| **`udisks2`** | **станція монтує флешку запису через `udisksctl mount`; без нього запису немає** | **[НОВЕ]** |
| **`chrony`** | **NTP-сервер для камери (§5)** | **[НОВЕ]** |

`util-linux` (`hwclock`) і `dbus` (потрібен udisks2) є в базовому Debian.

```bash
export DEBIAN_FRONTEND=noninteractive
apt-get update
apt-get install -y --no-install-recommends \
    gstreamer1.0-alsa udisks2 chrony
```

## 3. Вендорські пакети Rockchip/Mali  [є]

Не існують у жодному apt-репозиторії — переносяться `.deb`-ами з
`vrx-deps/vendor-debs/` і заморожуються (`apt-mark hold`), інакше
`autoremove`/`dist-upgrade` знесе їх мовчки:

`libmali-valhall-g610-g13p0-x11-gbm`, `librockchip-mpp1`, `librockchip-vpu0`,
`librga2`, `gstreamer1.0-rockchip1`.

Порядок: спершу пакети Debian, потім ці (`dpkg -i vendor-debs/*.deb &&
ldconfig`). Mali виграє в mesa за libEGL не конфліктом пакетів, а пріоритетом
шляху завантажувача (`/etc/ld.so.conf.d/00-aarch64-mali.conf`) — mesa
зносити не треба.

## 4. Мережа

| Хто | Адреса |
|---|---|
| **Станція (end1)** | **`192.168.1.1/24`, статично** — камера бере з неї шлюз і час |
| Камера | `192.168.1.10` |
| Борт (FIBER_WIND) | `192.168.1.122` |

Камера й борт шлють **бродкастом** — станція їх нікуди не підписує, лише
слухає. Фаєрвол не потрібен; якщо стоїть — ці порти мусять бути відкриті.

Що станція **приймає** (UDP):

| Порт | Що |
|---|---|
| 5600 | відео камери, H.265/RTP PT 97 |
| 5601 | звук камери, Opus/RTP PT 98 |
| 5001 | USB-захват камери, сирий MJPEG |
| 50122 | телеметрія борта |
| 50124 | чорна скринька борта |
| **123** | **NTP — станція роздає час камері** |

Що станція **шле**: HTTP на камеру (`192.168.1.10:80`, керування фазою).

## 5. Час — для камери  [НОВЕ]

Камера синхронізує годинник із `192.168.1.1` по NTP і штампує час у кадр.
Без NTP-сервера на станції в кадрі **`TIME NOT SET`** (так написано в
інтерфейсі камери).

- Часовий пояс: `Europe/Kyiv` (як на камері).
- RTC тримає час між вмиканнями.
- `chrony` роздає час підмережі; `local stratum 10` — щоб віддавав і **без
  інтернету**, з власного годинника (без цього рядка chrony вважає себе
  несинхронізованим і мовчить).

```bash
timedatectl set-timezone Europe/Kyiv
hwclock -w                                   # системний час -> RTC
cat > /etc/chrony/conf.d/vrx-ntp-server.conf <<'EOF'
# VRX-GL: роздача часу камері в ізольованій мережі станції.
allow 192.168.1.0/24
allow 192.168.0.0/24
local stratum 10
EOF
systemctl enable --now chrony
systemctl disable --now systemd-timesyncd 2>/dev/null || true   # клієнт, сервером не вміє
```

## 6. Звук  [НОВЕ]

Звукові карти, які станція відкриває за іменами (не за номерами):

| Карта ALSA | Вихід |
|---|---|
| `rockchiphdmi0` | HDMI |
| `rockchipes8388` | джек 3.5 мм |
| `rockchipdp0` | DP (USB-C) |

Потрібен лише пакет `gstreamer1.0-alsa` (§2). Вихід `Headphone` на ES8388
після старту системи вимкнений — станція вмикає його **сама** (libasound),
нічого налаштовувати не треба. Стан звуку (гучність, м'ют, поріг тривоги,
головний вимикач) станція зберігає сама в `audio.json`.

---

## 7. Носій запису (флешка)  [НОВЕ: udisks2]

Станція шукає знімний носій і монтує його через **`udisksctl mount -b`**
(потрібні `udisks2` і `dbus`, §2). Пише записи, журнали сеансів, звук,
чорну скриньку. Та сама флешка може нести й пакет оновлення `VRX-update/`.

---

## 8. Корінь станції: `/root/vrx-gl`

Наглядач визначає корінь сам (`/proc/self/exe`), тому важливо лише, щоб
бінарники лежали в `<корінь>/build/`. Вміст — те, що приїжджає повним
пакетом оновлення:

```
/root/vrx-gl/
├── build/vrx_gl, vrx_supervisor, uvc_relay, osd_editor
├── osd_config.json, osd_config2.json      розкладки OSD основного/додаткового екрана
├── osd_catalog.json, osd_icon_names.json
├── atlas.png, osd_glyph_info.bin, background.jpg
├── img/                                   картинки барів і горизонту
├── xorg.conf.d/20-modesetting.conf        X для редактора (glamor вимкнено, §12)
└── scripts/run.sh
```

Станція **сама створює й веде** (у пакет оновлення не кладуться ніколи):
`screen1..3.json` (пресети вікон), `audio.json` (звук),
`osd_glyph_kern.bin` (**ліцензія цієї станції**, §11).

## 9. Сервіси systemd

| Юніт | Що | |
|---|---|---|
| `vrx-gl.service` | наглядач: піднімає станцію й редактор | [є] |
| `vrx-update.service` | аплаєр оновлень із флешки на старті | [є, на релізі] |
| **`chrony.service`** | NTP для камери | **[НОВЕ]** |

`vrx-gl.service` (релізний варіант, `vrx-deps/vrx-gl.service`):

```ini
[Unit]
Description=VRX-GL station supervisor
After=network-online.target
Wants=network-online.target
Conflicts=display-manager.service

[Service]
Type=simple
ExecStart=/root/vrx-gl/build/vrx_supervisor
User=root
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal
PrivateDevices=no

[Install]
WantedBy=multi-user.target
```

Root обов'язковий: DRM master ексклюзивний, редактор піднімає власний X на
vt7, наглядач виставляє `net.core.rmem_max` для чорної скриньки.

## 10. Оновлення з флешки  [є]

- Ключ HMAC: **`/etc/vrx-update.key`, режим 600** — той самий, що
  `tools/update/vrx-update.key` у репо розробки. **Секрет**: на флешку й у
  git не кладеться.
- Аплаєр (`vrx-update.service`) на кожному старті шукає `VRX-update/` на
  флешках; версія відрізняється від встановленої — звіряє підписи й атомарно
  замінює файли. Деталі — `tools/update/README.md`.
- Оновлення пише **лише в корінь станції**: пакети й `/etc` ним не змінити —
  для цього і є цей документ.

---

## 11. Ліцензія  [є]

Прив'язка до microSD станції (CID, підпис Ed25519). Активація — по SSH
інструментами з `tools/` (`auto_activate.py`). Файл ліцензії —
`/root/vrx-gl/osd_glyph_kern.bin` (назва навмисно невиразна); **ніколи не
копіюється між станціями** — генератор пакета оновлення сам зупиняється на
ньому. SSH-доступ для активації — ключ із `tools/provision_key.pub`
(`install_ssh_key.sh`).

---

## 12. X для редактора розкладки  [є]

X існує лише заради `osd_editor`; станція показує через DRM/KMS повз нього.
Конфіг Xorg наглядач передає з кореня станції (`-configdir
<корінь>/xorg.conf.d`), а в ньому **`AccelMethod "none"`**: glamor поверх
libmali міняв місцями R і B на екрані. У `/etc` нічого міняти не треба.

## 13. Перевірка після встановлення

```bash
# пакети
dpkg -l gstreamer1.0-alsa udisks2 chrony | grep ^ii          # три рядки
gst-inspect-1.0 alsasink >/dev/null && echo alsasink ok
gst-inspect-1.0 mppvideodec >/dev/null && echo mpp ok
ldconfig -p | grep -m1 libEGL.so.1                           # шлях має містити /mali/

# мережа і час
ip -br addr show end1                                        # 192.168.1.1/24
timedatectl | grep "Time zone"                               # Europe/Kyiv
ss -ulnp | grep ':123 '                                      # chronyd слухає
chronyc clients                                              # з'явиться 192.168.1.10

# звук
cat /proc/asound/cards                                       # hdmi0, es8388, dp0

# станція
systemctl is-active vrx-gl chrony udisks2
journalctl -u vrx-gl -b | grep -E '\[звук|\[запис audio\]'   # виходи слухають 5601
test -r /etc/vrx-update.key && stat -c %a /etc/vrx-update.key   # 600
```

Остаточна перевірка — на камері: у кадрі дата й час замість `TIME NOT SET`,
у навушниках звук, на флешці з'являються `Zvuk_*.mka`.

## 14. Що помічено дорогою (не про образ, але важливо)

- **Ехо хартбіту (UDP 50911) станція не робить.** За протоколом борта кожен
  пристрій у сегменті мусить відповідати на пробу юнікастом, інакше борт
  вважає свій сокет заклиненим і ресетить W5500. Поки відповідає хтось інший
  (камера?), це непомітно; без них — обриви. Окрема задача на станцію.
